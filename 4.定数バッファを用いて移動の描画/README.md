![実行画面2](<docs/images/スクリーンショット 2026-10-15 044852.png>)

## やったこと
- インデックスバッファ（頂点4個・インデックス6個）で描いた四角形を、時間に合わせて左右に往復させた
- 定数バッファを2種類の方法でシェーダーに渡した
  - `b0`：`Transform`（World / View / Proj 行列）を **ルートCBV** で渡す
    - `SetGraphicsRootConstantBufferView(0, m_pCB[m_FrameIndex]->GetGPUVirtualAddress())`
  - `b1`：`MoveParam`（`OffsetX`）を **ルート定数** で渡す
    - `SetGraphicsRoot32BitConstants(1, sizeof(MoveParam) / 4, &m_MoveParam, 0)`
- 毎フレーム `OffsetX = sinf(経過時間)` を計算し、頂点シェーダーで `localPos.x += OffsetX` としてずらした
- ルートシグネチャのパラメータを2つにした
  - `params[0]`：`D3D12_ROOT_PARAMETER_TYPE_CBV`（register b0）
  - `params[1]`：`D3D12_ROOT_PARAMETER_TYPE_32BIT_CONSTANTS`（register b1、`Num32BitValues = 1`）

## 学んだこと
- **ルートCBV** はバッファ（リソース）のGPUアドレスを渡す。中身はMapしたメモリに書き込む
- **ルート定数** は値そのものをルートシグネチャに直接書き込む。バッファもディスクリプタも要らないが、使える量は少ない
- 定数バッファのサイズは256バイト境界に揃える必要がある（`struct alignas(256) Transform`）
- `Num32BitValues` は「32bit値が何個か」なので、`sizeof(MoveParam) / 4` になる
- 定数バッファはフレーム数ぶん（`m_pCB[FrameCount]`）用意している。今は Transform を毎フレーム書き換えていないが、書き換える場合は GPU が使用中のバッファを上書きしないよう `m_FrameIndex` のものに書く

## 詰まったこと
- 定数バッファをシェーダーに渡す **3つの方法の違い** が分からなかった
  → 「ルートシグネチャに何を置くか」で整理して理解した

| 渡し方 | ルートに置くもの | 必要なもの | 向いている用途 |
|--------|------------------|------------|----------------|
| ルート定数（`32BIT_CONSTANTS`） | 値そのもの | なし（バッファもディスクリプタも不要） | 数個の小さな値（今回の `OffsetX`） |
| ルートCBV（`CBV`） | バッファのGPUアドレス | 定数バッファのリソース | 行列など、ある程度大きいデータ（今回の `Transform`） |
| ディスクリプタテーブル | ディスクリプタヒープ内の位置 | リソース＋ディスクリプタヒープ＋CBVの作成 | 多数のリソースをまとめて渡す。テクスチャ（SRV）はこの方法でしか渡せない |

- ルートシグネチャ全体の大きさには上限（64 DWORD）がある。ルート定数は1値で1 DWORD、ルートCBVは1つで2 DWORD、ディスクリプタテーブルは1つで1 DWORD を使う
- 今回はルート定数とルートCBVの2つを使った。ディスクリプタテーブルは使っていないが、次のテクスチャ読み込みで必要になる
