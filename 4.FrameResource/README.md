# 004 フレームリソースで待ちを減らす

- 実行結果の見た目は [003](<../3.ConstantBuffer/>) と同じ。この章では、動かす仕組み（CPU と GPU の同期）だけを変えた。

## 手法
### World 行列で動かす
- 003 ではルート定数（`OffsetX`）を頂点シェーダーで足して動かしていたが、World 行列で動かすように変えた（ルート定数は使わなくなったので削除した）。
- 毎フレーム、`XMMatrixTranslation(sinf(経過時間), 0, 0)` を **今のフレーム用の定数バッファ** に書き込む。

  ```cpp
  m_pTransform[m_FrameIndex]->World = XMMatrixTranslation(sinf(static_cast<float>(m_Timer.GetTotalTime())), 0.0f, 0.0f);
  ```

### フレームリソース
- GPU が描画している間に CPU が次のフレームの準備を進められるよう、フレームごとに必要なものをバックバッファの数（`FrameCount = 2`）だけ用意している。

  | フレームごとに持つもの | 役割 |
  |---|---|
  | `m_pCommandAllocator[FrameCount]` | コマンドを記録するメモリ |
  | `m_pCB[FrameCount]` / `m_pTransform[FrameCount]` | 定数バッファ（Map したまま書き込む） |
  | `m_FenceCounter[FrameCount]` | そのフレームの GPU の処理が終わったかを判定する値 |

### 待つのは「次に使うフレームがまだ使用中のとき」だけ
- `Present` で、次のように同期している。
  1. 今のフレームのフェンスの値を GPU に `Signal` する
  2. バックバッファの番号（`m_FrameIndex`）を次に進める
  3. 次のフレームのリソースを GPU がまだ使っているとき（`GetCompletedValue()` が足りないとき）だけ待つ
  4. 次のフレームのフェンスの値を1つ進める
- 毎フレーム GPU の終了を待つのではなく、GPU が1フレーム遅れて追いかける形になるので、CPU と GPU が並行して動ける。

## 前と比べてできるようになったこと
- シェーダーを変えずに、定数バッファの World 行列だけで物体を動かせるようになった。
- CPU が GPU を毎フレーム待たなくなり、CPU と GPU が並行して動けるようになった。

## この章で新しく学んだこと
- GPU は CPU より遅れて描画しているので、CPU が次のフレームを準備している間も、GPU は前のフレームの定数バッファを読んでいることがある。
- そのため、定数バッファをフレームごとに分けて、`m_FrameIndex` のものにだけ書き込む。1つの定数バッファを毎フレーム書き換えると、GPU が読んでいる途中の値が変わってしまう。
- フェンスは「GPU がどこまで処理を終えたか」を数値で知るための仕組み。`Signal` で GPU に数値を書かせ、`GetCompletedValue` で今どこまで終わったかを調べる。
